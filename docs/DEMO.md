# CATCH-AI Demonstration Guide

This guide describes a factual demo using real persisted project data.

## Recommended flow

### 1. Open Command Center

Show the current backend status and persisted recovery jobs.

Do not claim a job is running unless the API reports RUNNING.

### 2. Open an actual recovery job

Show:

- evidence input;
- job identifier;
- execution state;
- engine executions;
- artifact count returned by the backend.

### 3. Inspect a real artifact

Open an artifact produced by an actual engine and show its recorded:

- source engine;
- file name/path;
- size;
- SHA-256 when available;
- validation state.

### 4. Inspect fragments

Show fragment records generated by the fragment-analysis pipeline.

If no evidence-backed relationships were established, display zero relationships rather than inventing a graph.

### 5. Show reconstruction state

A result such as NOT_SUPPORTED, INCOMPLETE, or AMBIGUOUS is valid when the evidence does not establish a unique reconstruction.

The demo should emphasize that uncertainty is preserved rather than hidden.

### 6. Refresh the application

Refreshing demonstrates that the displayed history comes from persisted backend data. It does not, by itself, prove crash-resume capability.

## Claims to avoid

Do not claim:

- every registered engine was executed;
- all engines run in parallel;
- every artifact is a deleted file;
- reconstruction is successful when it is not;
- the system is court-ready;
- evidence is immutable;
- reports are digitally signed;
- crash recovery/resume is implemented unless specifically tested.

## Closing explanation

CATCH-AI is designed to make recovery results traceable to actual processing. When the evidence is insufficient to establish a relationship or reconstruction, the platform reports that limitation instead of manufacturing a convincing-looking result.
